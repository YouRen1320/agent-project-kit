# 已有项目增量接入示例

这个示例演示如何把 Agent Project Kit 接入一个已经有 `AGENTS.md` 的普通项目。目标是补齐项目资料和高风险流程，同时保留原有技术约定；它不提供自动覆盖脚本。

## 接入前

假设项目已经有以下规则：

```markdown
# Pine Notes 项目规则

- 使用 pnpm，并保留现有锁文件。
- 修改数据库结构前先提交迁移方案。
- 前端组件使用现有设计令牌。
```

这些规则来自项目本身，Kit 不能把它们替换成通用模板内容。

## 文件处理表

| 路径 | 操作 | 原因 |
| --- | --- | --- |
| `AGENTS.md` | 人工合并 | 保留原规则，只增加必要的路由和交付要求 |
| `CLAUDE.md` | 检查后合并 | 保留已有 Claude Code 入口，避免重复规则 |
| `.agents/project/` | 新增并填写 | 存放从仓库证据确认的产品、命令、环境、接口和责任人 |
| `.agents/workflows/` | 按需新增 | 只保留项目真正会使用的流程 |
| `.agents/runbooks/` | 按风险新增 | 涉及数据、部署或回滚时保留对应门禁 |
| `.agents/templates/` | 可直接新增 | 报告和决策模板不应覆盖产品代码 |
| `.agents/skills/`、`.claude/skills/` | 按名称合并 | 同名 Skill 必须确定一份权威实现 |
| `scripts/`、`tests/` | 检查命名后新增 | 避免覆盖项目已有脚本，并把校验接入现有 CI |

## 接入后的根规则

合并后的 `AGENTS.md` 应同时包含两类信息：

```markdown
# Pine Notes 项目规则

## 项目原有约定

- 使用 pnpm，并保留现有锁文件。
- 修改数据库结构前先提交迁移方案。
- 前端组件使用现有设计令牌。

## Agent Project Kit 路由

- 开始任务前读取 `.agents/index.md` 和相关项目资料。
- 架构、接口、数据模型或跨组件变更先比较方案并获得明确确认。
- 数据库、部署和回滚操作使用对应运行手册。
```

项目事实随后写入 `.agents/project/` 的六份资料。命令只能来自实际清单或已运行结果；无法确认的责任人、环境和发布规则应明确标为未知并指定后续确认人，不能为了通过检查而编造。

## 验证顺序

```sh
./scripts/validate-project-profile.sh
./scripts/validate.sh
./scripts/test.sh
```

然后运行项目自己的安装、静态检查、测试和构建命令，并分别确认 Codex 与 Claude Code 能加载合并后的入口。

仓库测试中的 `test_existing_project_adoption_preserves_original_rules_and_validates` 会在临时副本里保留一条原项目规则、填完项目资料，再运行项目资料校验和整套模板校验。它验证的是增量接入的安全底线，不代表真实项目的命令、环境或责任人已经确认。

## 回滚

如果试用后决定不采用，恢复接入前的入口文件，只删除本次新增的 Kit 路径。不要回滚同一分支中无关的产品改动。
