# Security Policy

## Supported Versions

Security fixes are applied to the latest 0.1.x release while the project is in its initial development phase.

## Reporting A Vulnerability

Do not open a public issue containing a vulnerability, credential, personal data, or private project information.

Use the repository's private vulnerability-reporting feature when it is available. If that feature is unavailable, email [lijunpg@foxmail.com](mailto:lijunpg@foxmail.com). Include:

- A concise description and affected version.
- A sanitized reproduction or proof of impact.
- The affected workflow, runbook, skill, script, or documentation path.
- A suggested mitigation when available.

Do not include live credentials, production dumps, unrestricted infrastructure details, or data belonging to another person.

## Security Scope

Security reports may include:

- Guidance that could cause unsafe or unauthorized operations.
- Validation that fails to detect public-data leakage as documented.
- Skills or scripts that execute more broadly than described.
- Installation or upgrade behavior that overwrites project rules or private material.

The maintainers will acknowledge a report, assess severity, coordinate a fix, and disclose it after users have a reasonable upgrade path.
